Диагностика сети AtomConnect

Небольшой скрипт для Windows, который шаг за шагом проверяет, почему AtomConnect не работает в вашем подключении: DNS, блокировки адресов, TLS, WebSocket, UDP/TURN. Результат — текстовый файл-отчёт, который вы отправляете разработчику.

Что делает и чего не делает скрипт. Он только читает настройки системы (версия Windows, прокси, DNS-серверы, корневые сертификаты, имена запущенных программ) и отправляет небольшие тестовые запросы на AtomConnect, Cloudflare, Google, Яндекс и зеркало Ubuntu. Он ничего не устанавливает, не меняет настройки и ничего никуда не отправляет сам: отчёт сохраняется в файл рядом со скриптом, а отправлять его или нет — решаете вы. Скрипт — обычный текст, он целиком показан ниже, его можно прочитать до запуска. Имя компьютера, имя пользователя и MAC-адреса в отчёте скрыты. В отчёте будут ваш внешний IP-адрес и название провайдера (ASN): это нужно, чтобы понять, где блокировка.

Шаг 1. Получите скрипт (способ А, рекомендуется: ничего не скачивается)

Браузеры и антивирусы часто блокируют скачанные файлы .bat. Вставка текста в Блокнот это обходит.

  1. Нажмите кнопку Копировать скрипт ниже (текст выделится и скопируется).
  2. Откройте Блокнот: Пуск, введите notepad, Enter. Вставьте текст: Ctrl+V.
  3. Меню Файл, Сохранить как. Внизу в поле Тип файла выберите Все файлы. В поле Имя файла введите atomconnect-diag.bat. Кодировка: ANSI (по умолчанию). Папка: Рабочий стол. Нажмите Сохранить и закройте Блокнот.

Способ Б: нажмите «Скачать .txt», затем переименуйте файл в atomconnect-diag.bat (если расширения не видны: Проводник, Упорядочить, Параметры папок и поиска, Вид, снимите галочку «Скрывать расширения для зарегистрированных типов файлов»).

Шаг 2. Запустите

  1. Дважды щёлкните atomconnect-diag.bat на Рабочем столе. Если Windows спросит «Запустить этот файл?» или покажет предупреждение системы безопасности, нажмите Запустить. Откроется чёрное окно.
  2. Нажмите Enter, чтобы начать. Проверка идёт примерно 3–5 минут, в окне бегут строки. Не закрывайте окно и не нажимайте клавиши, пока она идёт. Красные строки — это нормально: именно так отображаются найденные проблемы.
  3. Если антивирус заблокировал или удалил файл: не отключайте антивирус, просто напишите разработчику, что именно он сообщил.

Шаг 3. Проверка в Chrome (в конце, примерно 1–2 минуты)

Если установлен Chrome, скрипт спросит Run the browser capture now? (Y/n). Нажмите Enter (да). Откроется Chrome с отдельным чистым профилем (ваши вкладки и пароли не затрагиваются).

  1. Дождитесь, пока в большом поле на странице появится строка --- done --- (до 40 секунд).
  2. Нажмите кнопку Select all на странице, затем Ctrl+C.
  3. Вернитесь в чёрное окно и нажмите Enter. Откроется Блокнот: вставьте текст (Ctrl+V), сохраните (Ctrl+S) и закройте Блокнот.
  4. Chrome закроется сам (если нет — закройте его, затем нажмите Enter в чёрном окне).

Если Chrome не установлен или вы отказались, этот шаг пропускается, это допустимо.

Шаг 4. Отправьте результат

В конце появится зелёная надпись DONE и откроется папка с файлами (на Рабочем столе). Нужны:

  • AtomConnect-diag-ДАТА-ВРЕМЯ.txt — основной отчёт (всегда);
  • AtomConnect-netlog-ДАТА-ВРЕМЯ.cab — журнал сети Chrome (если появился).
  1. Откройте .txt в Блокноте и просмотрите: там нет паролей и ваших файлов, только сетевые настройки и результаты проверок.
  2. Выделите оба файла, щёлкните правой кнопкой, Отправить, Сжатая ZIP-папка. Получится один .zip.
  3. Отправьте .zip по почте на alexander.uspensky@gmail.com (тема: AtomConnect diagnostics) или тем мессенджером, которым вы уже общаетесь с разработчиком.
  4. Если вложения не отправляются: откройте .txt в Блокноте, Ctrl+A, Ctrl+C и вставьте текст прямо в письмо или сообщение (.cab в этом случае пропустите).

Если что-то пошло не так

Окно закрылось сразу, появились длинные красные ошибки, скрипт завис больше чем на 10 минут: сделайте фото экрана или скриншот и отправьте вместе с .txt, если он появился (он сохраняется по ходу работы, даже неполный полезен). Можно закрыть окно и запустить скрипт ещё раз.

AtomConnect network diagnostics

A small Windows script that tests, step by step, why AtomConnect does not work on your connection (DNS, blocked addresses, TLS, WebSocket, UDP/TURN). It produces a text report that you send to the developer.

What it does and does not do. It only reads system settings (Windows version, proxy, DNS servers, installed root certificates, names of running programs) and sends small test requests to AtomConnect, Cloudflare, Google, Yandex and an Ubuntu mirror. It installs nothing, changes no settings and uploads nothing: the report is saved as a file next to the script and you choose whether to send it. It is plain text, shown in full below, so you can read it first. PC name, user name and MAC addresses are masked. The report does contain your public IP address and ISP (ASN), which is needed to locate the blocking.

Step 1. Get the script (option A, recommended: nothing is downloaded)

Browsers and antivirus programs often block downloaded .bat files. Pasting the text into Notepad avoids that.

  1. Click Copy script below (the text is selected and copied).
  2. Open Notepad (Start, type notepad, Enter) and paste with Ctrl+V.
  3. File, Save As. Set Save as type to All files, file name atomconnect-diag.bat, encoding ANSI (default), folder Desktop. Save and close Notepad.

Option B: click “Download as .txt” and rename the file to atomconnect-diag.bat (if extensions are hidden: Explorer, Organize, Folder and search options, View, untick “Hide extensions for known file types”).

Step 2. Run it

  1. Double-click atomconnect-diag.bat on the Desktop. If Windows asks “Do you want to run this file?” or shows a security warning, choose Run. A black window opens.
  2. Press Enter to start. It takes about 3-5 minutes and prints lines as it goes. Do not close the window or press keys while it runs. Red lines are normal: that is how problems it finds are shown.
  3. If your antivirus blocks or deletes the file, do not disable the antivirus; just tell the developer what it reported.

Step 3. Chrome check (at the end, about 1-2 minutes)

If Chrome is installed, the script asks Run the browser capture now? (Y/n). Press Enter (yes). Chrome opens with a separate clean profile (your tabs and passwords are not touched).

  1. Wait until the big text box on the page shows --- done --- (up to 40 seconds).
  2. Click the Select all button on the page, then press Ctrl+C.
  3. Go back to the black window and press Enter. Notepad opens: paste (Ctrl+V), save (Ctrl+S) and close Notepad.
  4. Chrome closes by itself (if not, close it and press Enter in the black window).

If Chrome is not installed or you answer no, this step is skipped; that is fine.

Step 4. Send the result

At the end a green DONE message appears and the folder with the files opens (the Desktop). You need:

  • AtomConnect-diag-DATE-TIME.txt: the main report (always);
  • AtomConnect-netlog-DATE-TIME.cab: Chrome network log (if it was created).
  1. Open the .txt in Notepad and look through it: it contains no passwords or personal files, only network settings and test results.
  2. Select both files, right-click, Send to, Compressed (zipped) folder. This gives one .zip.
  3. Email the .zip to alexander.uspensky@gmail.com (subject: AtomConnect diagnostics) or send it through the messenger you already use with the developer.
  4. If attachments will not send: open the .txt in Notepad, Ctrl+A, Ctrl+C and paste the text straight into the email or message (skip the .cab then).

If something goes wrong

The window closes at once, long red errors appear, or it hangs for more than 10 minutes: take a photo or screenshot of the window and send it, together with the .txt if one exists (it is saved as it goes, so even a partial one helps). You can close the window and run the script again.
